# 本地 DSH 养大肥鱼方案

> 依据 2026-11-25 的联网检索与仓库核实；DSH 宿主版本 `0.2.2-rc.5`（`desktop` profile）。插件版本与兼容性以各自 README / `package.json` 为准，安装前复核。

## 0. 一句话方案

**dsh-pet 提供身体，dsh-soul-md 提供人设与记忆，dsh-proactive 提供主动，bili/douyin-scroll 提供刷流，multi-root 解决跨工作区。** 其余都是可选增强。

## 1. 核心插件

### 1.2 可选（按需，别全装）

| 需求 | 插件 | 说明 |

| 想要 Live2D + 口型 + 本地音色 | [`dsh-dstuber`](https://github.com/T-MS-Reyes/dsh-DSTuber) | Windows only，Edge TTS / GPT-SoVITS，16 种情绪；0.1.0，较重 |

### 1.3 明确不要同时装

- 两个以上「宠物/桌宠」插件：DOM 浮层、桌面窗口、系统通知都会重复，且吃掉两份动画内存。
- 两套 TTS：pet、voice-chat、dstuber 同时开会出现双重朗读。
- 刷流插件的「自动评论」与任何其他评论链路：账号写操作只留一个出口。

## 2. 需要重写的部分

### 2.1 必须做（按优先级）

| # | 事项 | 形态 | 估算 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | **人设与边界** | 内容，不是代码 | 1–2 天 | 写进 soul-md 人设卡或 `AGENTS.md`：身份、语气、称呼、禁区、记忆规则、主动频率。旧 AstrBot 的 POLICY 可作素材 |
| 2 | **记忆迁移器** | 一次性脚本 | 0.5–1 天 | 旧中央 Memory 的 SQLite → `soul-md` 的 `core.md` / `topics/*.md`；保留来源与时间，丢掉领域短期记录 |
| 3 | **日报桥** | 配置为主 | 0.5 天 | bili/douyin 的日报写在 `~/.dsh/*-duty/out/`；用 multi-root 把这两个目录挂成**只读附加根**，proactive 的 prompt 直接读当天文件 |
| 4 | **视频对话补齐** | 配置 + 少量胶水 | 1 天 | 普通会话默认拿不到「读字幕聊视频」；把 bili-scroll 家目录里的 `mcp_server.py` 按 MCP bundle 挂给主会话 |
| 5 | **主动策略调参** | 配置 | 0.5 天 | 安静时段、每日预算、默认 prompt、静默收尾话术；先每天 1 次，别一上来心跳 |

### 2.2 可选

- 自定义 `.dshpet` 角色包（用 `dsh-bigfish-pet-maker` Skill 或 dsh-pet 素材链），1–3 天。
- 旧 Memory 服务本地 Docker 化 + MCP 接入：保留分层与候选审批，但多一个常驻容器，1–2 天。

### 2.3 不需要重写

agent loop、事件溯源会话、工具系统、Schedule、Web UI、权限沙箱、子代理、压缩——全部复用。用户想学的部分正好是这些，读源码即可，不必改。

## 3. 工作区文件夹结构

### 3.1 推荐布局

```text
D:\dafeiyu\                        # 大肥鱼主工作区（主根，读写）
├── AGENTS.md                      # 工作区级指令：身份、边界、记忆与主动规则
├── README.md                      # 这个工作区是干什么的
├── Journal\                       # 日报归档（从刷流 out 目录复制或软链）
│   ├── bili\
│   └── douyin\
├── Notes\                         # 长期笔记、决定、待跟进
├── Inbox\                         # 待审：候选记忆导出、待看视频清单
├── Media\                         # 封面/截图缓存（不进 Git）
├── Skills\                        # 自定义技能（等价 .dsh/skills）
└── .gitignore                     # 排除 Media\、State\、凭据
```

```text
%USERPROFILE%\.dsh\                # 不放工作区，单独备份
├── profiles\desktop\              # 插件与配置
├── soul-md\memory\                # 人设卡与分层记忆
├── proactive\                     # 闹钟、runs.jsonl、config.json
├── bili-duty\                     # B站刷流：凭据、out\、duty.log
└── douyin-duty\                   # 抖音刷流：Cookie、out\、duty.log
```

### 3.2 每条规则

- `D:\dafeiyu` 只放大肥鱼的东西；工作代码不放进来。
- 凭据永远不进 workspace，也不进 Git；`~/.dsh` 单独备份。
- `Journal\` 可以是软链，也可以是每天复制的副本；软链更省事，但要确认沙箱允许。
- `Media\`、`State\` 进 `.gitignore`；workspace 本身可以做成私有 Git 仓库，换机即恢复。
- 日报、记忆、闹钟是三份独立数据，备份要分别做。

## 4. 跨工作区怎么处理

### 4.1 先理解原生限制

DSH 的 Workspace 只是「目录记录 + 会话分组」，对模型不可见；真正决定权限的是会话创建时写死的 `SessionHeader.cwd`，而 `workspace-write` 沙箱只覆盖这个目录。所以**原生不支持一个会话同时读写两个工作区**。

### 4.2 三条可用通道

| 通道 | 做法 | 适合 |
| --- | --- | --- |
| 文件 | multi-root 把另一个目录登记为附加根：`/workspace-folders add D:\work --read-only` | 让大肥鱼读工作资料，但不许改 |
| 记忆 | soul-md 的 `memory.scope=global`，或为每个工作区指定人设卡 | 跨工作区共享「她记得的事」 |
| 会话 | 会话引用 / 会话搜索，跨会话翻旧账 | 找回上次聊到哪 |

### 4.3 推荐拓扑

```text
D:\dafeiyu  ──主根(rw)──┐
                        ├── 大肥鱼会话：主根 rw + D:\work 只读 + 刷流 out 只读
D:\work     ──独立工作区─┘

D:\dafeiyu-bridge ──两边都挂 rw──  只放明确要交换的文件
```

规则：

1. **单向只读**：大肥鱼能读工作目录，工作会话**不**挂大肥鱼目录；防止她写进代码。
2. **桥目录显式化**：确需双向交换时，只用 `D:\dafeiyu-bridge`，两边都挂读写，别把整个 home 挂进去。
3. **最小权限**：附加根默认 `--read-only`；要写才升 `--read-write`，且先确认路径。
4. **Windows 限制**：UNC、映射网络盘、`\\?\` 不能作为附加根。
5. **升级锁定**：multi-root 是精确版本 allowlist，DSH 升级前先看它是否支持新版本。
6. **人设按工作区**：soul-md 的解析顺序是「会话选择 → 工作区人设 → 默认卡」，工作区可以给一个更克制的卡，避免上班时被撒娇打断。

## 5. 落地顺序与验收

| 周 | 做什么 | 验收 |
| --- | --- | --- |
| 1 | 装 dsh-pet + soul-md；建 `D:\dafeiyu`；写人设卡 | 连续聊 3 天，人设稳定，工作区不串 |
| 2 | 装 proactive；每天 1 次唤醒，安静时段 23:00–08:00 | 冷会话能被唤醒；无事时静默收尾，不留长上下文 |
| 3 | 装 bili/douyin-scroll（只读）+ multi-root 挂 out 目录 | 日报出现在 `Journal\`；proactive 能读并总结 |
| 4 | 记忆迁移脚本；旧 Memory 备份归档 | 旧偏好能在新会话被召回 |
| 5+ | 可选：语音、Live2D、自定义角色包 | 按需 |

## 6. 主要风险

1. **记忆能力降级**：soul-md 是文件 + 关键词，不是向量 + 分层候选；旧 Memory 的「候选审批、领域隔离」需要自己补。
2. **主动插件较新**：dsh-proactive 12 个 open issue，先用内置 Schedule 兜底，proactive 只做增强。
3. **dsh-pet 的对话与人设可能两套**：宠物自带聊天通道，需把同一份人设灌进去，或只让它做「表现层」。
4. **Windows 验证缺口**：dsh-bigfish 未在 Windows 验证；dsh-dstuber 是 Windows only 但 0.1.0。
5. **单机即全部**：没有服务器兜底，备份与恢复要当成一等公民。
