# 2026-11-25 架构转向：用本地 DSH 承载大肥鱼

- 状态：**已决定（用户 2026-11-25 口头决定），未实施**
- 关联：[本地 DSH 养大肥鱼方案](2026-11-25-本地DSH养大肥鱼方案.md)、[刷流插件接入冲突评估](../功能更新/2026-11-25-刷流插件接入冲突评估.md)

## 背景

原架构：阿里云 ECS 上的 AstrBot + 独立聊天 App（Windows/Android）+ 聊天网关 + 中央 Memory + 抖音侧车。2026-11-25 用户决定放弃云端部署，改用本机 DSH 作为大肥鱼。

## 决定

1. 大肥鱼的主形态改为**本机 DSH**（当前 0.2.2-rc.5，`desktop` profile）。
2. AstrBot、聊天网关、独立 App 进入退役流程；服务器保留备份 30 天。
3. 刷流能力改用 DSH 生态插件（bili-scroll / douyin-scroll），先只读。
4. 记忆优先本地文件式方案，旧中央 Memory 只作为迁移来源与归档。

## 理由评估

| 用户理由 | 评估 |
| --- | --- |
| 省服务器租费 | 成立。但 ECS 同时承载 Memory、抖音侧车、网关；撤掉后这三样要么本地化，要么放弃。省的是固定租费，token 费用转到个人账户。 |
| 插件质量高、重写少 | 对「刷流」成立（bili-scroll 2.5.3、douyin-scroll 0.7.10），对「陪聊」不成立——人设、记忆、主动仍要自己搭。 |
| 工作工程里提供拟人化服务 | 可行但需隔离。DSH 会话绑定工作目录，共用工作区会让人设与工程上下文互相污染。 |
| 源码适合学习 Agent 框架 | 成立，且是四条里最长期的一条。DSH 的事件溯源会话、agent loop、preset、schedule 都可读。 |

## 明确代价

1. **手机端消失**：App 退役后，Android 上没有大肥鱼。
2. **7×24 消失**：宿主关闭即停；主动消息只进 DSH 会话（已实测）。
3. **记忆需迁移**：旧中央 Memory 的分层/候选/领域隔离不能直接沿用，需导出或改接。
4. **单机故障即全停**：没有服务器兜底，备份责任转到本机。

## 迁移阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 0 冻结 | ECS 快照；导出 Memory、凭据、聊天历史；保留 30 天 | 备份可恢复 |
| 1 最小闭环 | 独立 workspace + 人设 + 记忆插件，只聊天 | 连续 3 天，人设不串工作 |
| 2 能力接入 | 刷流只读、主动唤醒、日报桥 | 日报进会话，主动消息可静默 |
| 3 退役 | 停 AstrBot/网关/App，释放 ECS | 30 天无回退需求 |

## 回滚

- 阶段 0 的 ECS 快照与凭据导出是回滚基础；30 天内可原样恢复。
- DSH 侧：移除新增插件、删除 workspace 即可；`~/.dsh` 下的记忆与闹钟数据单独备份。
- 不删除旧 Memory 数据，直到阶段 3 验收完成。

## 待确认

1. 手机端是否必须；若必须，DSH 不能完全替代 App。
2. 工作区是否共用；建议不共用（见方案文档第 4 节）。
3. 记忆选型：soul-md 文件式，还是保留旧 Memory 服务本地跑。
