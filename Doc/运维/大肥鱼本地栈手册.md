# 大肥鱼本地栈运维手册

> 适用：本机 DSH + `D:\大肥鱼` + MemoryService v2 + 本地 Ollama。
> 最后核对：2026-11-26。

## 1. 组件与路径

| 组件 | 位置 / 入口 | 说明 |
| --- | --- | --- |
| DSH | 桌面应用；Web GUI 端口每次启动可能变化 | 宿主，提供会话、工具、插件 |
| 身体工作区 | `D:\大肥鱼` | 仓库根；人设、文档、日报入口 |
| Memory 服务 | `D:\大肥鱼\MemoryService` | Python + SQLite + MCP stdio |
| 记忆库 | `%USERPROFILE%\.dsh\memory-v2\memory.db` | 不进 Git |
| 召回桥 | `D:\dsh-plugins\dafeiyu-memory-recall` | DSH 插件，`link:` 安装 |
| 刷流插件 | `dsh-bili-scroll` / `dsh-douyin-scroll` | 装在 profile，只读 |
| Ollama | `http://127.0.0.1:11434`，模型 `bge-m3` | 本地嵌入；关掉会退回关键词 |
| 备份 | `D:\大肥鱼\Backups` | 已 `.gitignore` |

## 2. 日常检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\大肥鱼\Tools\health.ps1
```

输出应包含：

```text
memoryMcp: True
ollama: true
embeddingModel: True
memoryDb: True
events=... active=... candidates=... core=...
lastBackup: ...
```

任何一项 false，按第 6 节排查。

## 3. 启动与停止

- **DSH**：正常打开桌面应用即可。MCP 服务由 DSH 按配置拉起，不需要手动开。
- **Ollama**：`ollama serve`（后台）。关掉后语义召回退回关键词，不报错。
- **MCP 服务**：由 DSH 管理；改了 `mcp_server.py` 后需要重启 DSH 或让客户端重连。

## 4. 记忆操作（在对话里直接用）

| 想做什么 | 工具 |
| --- | --- |
| 查看状态 | `memory_stats` |
| 记住一件事 | `memory_ingest`（产生候选）→ `memory_promote`（确认） |
| 看候选 | `memory_candidates` |
| 拒绝候选 | `memory_reject` |
| 恢复误删 | `memory_restore` |
| 召回 | `memory_recall`（关键词+精排）、`memory_semantic_recall`（向量） |
| 补向量 | `memory_embed` |
| 核心记忆 | `memory_core_propose` → `memory_core_confirm` → `memory_core_list` |
| 每日摘要 | `memory_digest_generate` / `memory_digest_get` |
| 衰减 | `memory_decay`（默认 dry-run） |
| 物理清理 | `memory_purge`（必须 `confirm=true`，只清过期 deleted） |
| 手动心跳 | `memory_tick` |

自动路径：MCP 服务内每 10 分钟跑一次「会话增量入库 + 当天摘要 + stale 监控」；召回桥在 `system-prompt/assemble` 注入相关记忆，**仅限 `D:\大肥鱼` 工作区**。

## 5. 备份与恢复

```powershell
# 备份（一致性快照 + 人设 + 配置）
python D:\大肥鱼\MemoryService\backup.py --target D:\大肥鱼\Backups

# 校验
python D:\大肥鱼\MemoryService\backup.py --verify D:\大肥鱼\Backups\dafeiyu-YYYYMMDD-HHMMSS.zip

# 恢复（先停 DSH；默认拒绝覆盖，--force 会先留存旧库）
python D:\大肥鱼\MemoryService\backup.py --restore D:\大肥鱼\Backups\<zip> --force
```

## 6. 常见问题

| 现象 | 先看 | 处理 |
| --- | --- | --- |
| 记忆工具不可用 | `health.ps1` 的 `memoryMcp` | 重启 DSH；检查 `cordis.patch.yml` 的 `mcp-dafeiyu-memory` 行 |
| 语义召回变成关键词 | `ollama` / `embeddingModel` | `ollama serve`；`ollama list` 确认 bge-m3 |
| 召回不注入 | 会话是否在 `D:\大肥鱼` | 其它工作区按设计不注入；改 `DFY_MEMORY_WORKSPACES` 后需重启 |
| 召回每次很慢 | 首次加载模型 | 桥会在启动时预热；仍慢则查 Ollama 负载 |
| 日报跑不了 | `bili_status` / `douyin_status` 的 `loggedIn` | 扫码登录；B站字幕、抖音候选都需要凭证 |
| 提示插件未激活 | 插件管理页条目 | 看诊断；卸载后重装，注意 npm 源与版本 |
| 记忆库变大 | `memoryDbMB` | 正常增长；清理用 `memory_purge`，压缩用 SQLite VACUUM（需停服务） |

## 7. 安全边界

- 仓库 `kiannaad/-Build` 是 **public**：只放文档、人设、技能；记忆/日报/凭据默认被 `.gitignore` 排除。
- 记忆只进 `D:\大肥鱼` 的对话；其它工作区要显式放行。
- `restricted` 记忆不嵌入、不默认召回。
- 凭据（Cookie、Token）不写入文档、不提交、不在回复中展示。
- 插件源码不随仓库走；换机按文档重装。

## 8. 周期检查

- 每天：`health.ps1` 看 MCP/Ollama/备份。
- 每周：跑一次 `backup.py`，确认备份可校验；看 `memory_stats` 的 candidates 是否堆积。
- 每月：验证一次 `--restore` 到临时目录（不要覆盖线上库）；检查 DSH 与插件版本。
