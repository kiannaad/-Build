# 大肥鱼重建文档 v1

- 版本：v1（2026-11-25）
- 状态：**阶段 1 完成、阶段 3 部分**；`dsh-pet 0.4.9`（desktop 单形态）、`dsh-soul-md 0.12.5`（人设卡已生效）、`multi-root 0.1.24`、`dsh-bili-scroll 2.5.3`、`dsh-douyin-scroll 0.7.10` 已装；刷流全部只读，日报目录已接入 `Journal/`；`dsh-proactive` 不兼容，暂用内置 Schedule
- 依据：本机 DSH `0.2.2-rc.5`（`desktop` profile）、2026-11-25 的插件检索与仓库核实、旧云端 Memory 设计

## 0. 一句话

**DSH 当大脑，`D:\大肥鱼` 当身体，插件当感官，自建 Memory v2 当长期记忆，`dsh-proactive` 当主动。** 旧 AstrBot/网关/App 退役，只保留回滚备份。

## 1. 目标与非目标

### 目标

1. 在本机 DSH 里长期陪伴主人，人设稳定、记忆可追溯、主动有分寸。
2. 能读 B站/抖音内容并给出有证据的推荐与日报。
3. 记忆可纠错、可遗忘、可恢复、可迁移；数据在本机可读可备份。
4. 代码与文档可同步到 GitHub，换机可恢复。

### 非目标

- 不做 7×24 在线：DSH 不在，她就不在。
- 不做手机端：独立 App 已退役。
- 不追求无人值守的账号操作：评论/私信默认关闭，写操作单出口。

## 5. 记忆系统 v2（核心改写）

### 5.1 五层模型

| 层 | 内容 | 权威性 | 用途 |
| --- | --- | --- | --- |
| L0 工作记忆 | 当前会话、最近几轮、压缩摘要 | 临时 | 理解「刚才/继续/这个」 |
| L1 每日摘要 | 当日重要事件、情绪脉络、未完成事项 | 可重建 | 时间线、日记、主动系统 |
| L2 语义记忆卡 | 摘要、标签、重要度、置信度、向量、来源引用 | 可重建 | 日常召回 |
| L3 事件原始层 | 对话事件、共同经历、承诺、来源 | 权威 | 追溯、纠错、重建 |
| L4 核心记忆 | 稳定身份事实、关系、长期约定、边界 | 权威 | 相关场景优先 |

规则：L1/L2 不得覆盖 L3；每条 L2 必须引用至少一个 L3 事件；L4 只能经确认或受控晋升修改；推断与助手生成内容不得写成用户事实。

### 5.2 存储

SQLite（WAL）+ FTS5 + `sqlite-vec`；表：

`events`（L3）、`memories`（L2）、`memory_sources`、`memory_embeddings`、`core_memories`（L4）、`daily_digests`（L1）、`memory_audit`、`jobs`。

L2 额外字段：`half_life_days`、`last_reinforced_at`、`reinforcement`、`archived_at`、`sensitivity`（`public_safe` / `private` / `restricted`）。

### 5.3 写入

1. 一轮成功结束后提交用户消息、回复、时间、来源、`turn_id`；
2. 敏感信息过滤；
3. 幂等写入 L3；
4. 后台提取候选；
5. 事实归属 / 长期价值 / 敏感 / 重复 / 冲突检查；
6. 合格候选写 L2 并生成向量；
7. 高重要度稳定事实进入 L4 待确认或受控晋升；
8. 全流程写审计。

### 5.4 召回

- 候选：向量 Top 30 + FTS5 Top 20；
- 过滤：删除、失效、被替代、场景不可见、敏感级别不匹配；
- 精排：

```text
score = similarity × (
    0.55
  + 0.15 × importance
  + 0.10 × confidence
  + 0.10 × recency
  + 0.05 × reinforcement
  + 0.05 × source_affinity
)
```

- 输出 4–6 条，预算 800–1200 tokens，类型与主题做多样性约束。

### 5.5 艾宾浩斯衰减

记忆保持率：

```text
retention = 0.5 ^ (Δt / half_life_eff)
half_life_eff = half_life_days × (1 + 0.5 × reinforcement)，上限 3×
```

初始半衰期：

| 类型 | 半衰期 |
| --- | ---: |
| 一般事件 | 30 天 |
| 共同经历 | 180 天 |
| 兴趣偏好 | 120 天 |
| 临时计划/承诺 | 按截止日期 |
| 用户确认的稳定事实 | 365 天 |
| L4 核心记忆 | 不衰减 |

- 每日任务重算 `recency`；低于阈值先**归档**（可恢复），不物理删除。
- 只被模型读取不增加 `reinforcement`；用户再次确认或独立证据才增加。
- 彻底删除需用户明确要求，活动库删正文与向量，审计只留最小证明。

### 5.6 向量

- 模型：硅基流动 `BAAI/bge-m3`，1024 维；模型 ID/维度/版本/内容哈希随向量保存。
- 换模型必须重建，不混用；嵌入失败退化为关键词召回，后台补生成。
- `restricted` 内容不发送给嵌入服务。

### 5.7 与 DSH 的接口

- 本地常驻服务：Python + FastMCP + SQLite，**只监听回环**。
- DSH 侧两条路：
  1. MCP bundle 注册只读工具：`memory_recall`、`memory_read_core`、`memory_audit`；
  2. 小型适配插件：`agent/pre-step` 自动召回注入，轮次成功事件提交写入（等价旧 AstrBot 适配器）。
- 写工具：`memory_remember`、`memory_correct`、`memory_forget`、`memory_restore`、`memory_core_propose`、`memory_core_confirm`。
- 与 soul-md 的边界：**soul-md 只保留人设**，关闭它的记忆注入与 `memory_*` 工具，避免双记忆。

## 10. 风险

1. **记忆改写工作量大**：五层 + 向量 + 衰减 + 审计，至少 1–2 周；先做 L3/L2/召回，L1/L4 后补。
2. **双记忆冲突**：soul-md 与 v2 同时注入会重复；必须显式关闭一边。
3. **proactive 较新**：12 个 open issue；先小范围验证，保留 Schedule 兜底。
4. **公开仓库**：当前 public，任何私密数据都可能泄露；默认排除是底线，不是保险。
5. **单机即全部**：没有服务器兜底；备份与恢复要定期演练。
