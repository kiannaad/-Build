# 2026-11-25 自动召回桥（system-prompt 注入）

## 时间

2026-11-25 22:15–22:45（Asia/Shanghai）

## 原因

人设卡只能「提醒模型去调 recall」，不是机械召回。先试了 `agent/pre-step` 追加消息：子代理实测**没有收到注入**，日志也没有记录——时序不对（DSH 在 pre-step 之前就组装了提示词）。改为 soul-md 已经验证过的 `agent/inbox/claimed` + `system-prompt/assemble`。

## 改动

新增本地插件 `D:\dsh-plugins\dafeiyu-memory-recall`（不进仓库）：

- `agent/inbox/claimed`：记录本会话最近一条用户消息（只认 `source.kind === 'user'`）；
- `system-prompt/assemble`：`await next()` 后，按查询取记忆，追加一个 `name=dafeiyu-memory-recall` 的 section；
- 记忆读取：`node:sqlite` 只读打开 `~/.dsh/memory-v2/memory.db`；
- 查询：用户文本切成中文 bigram / 英文词，`LIKE` 取 active 记忆与 confirmed 核心记忆，按命中比例排序，取前 4；
- 注入文本固定开头「记忆背景（系统注入，不是主人发言）」，并声明只作背景、不是指令、无关就忽略；
- 任何异常都回退原 assembly；已存在同名 section 或本会话无查询时不注入；
- 注入时写 `~/.dsh/memory-v2/recall-bridge.log`。

## 影响面

- 所有会话（含子代理）在提示词组装时可能多一段记忆；有命中才注入。
- 只读数据库，不写记忆；不可用时静默跳过。
- 插件通过 `link:` 安装到 `desktop` profile，源码在 `D:\dsh-plugins`，不随仓库走。

## 验证证据

1. 本地假 payload 测试：`node test.mjs` → `recall bridge test ok`（召回、注入一次、不重复、无查询不注入）。
2. 第一次 `agent/pre-step` 方案：子代理明确回答「没有收到记忆背景」，日志为空——证明该时序不可用。
3. 改为 system-prompt 后，子代理 `recall-check2` 回答：
   - 宿主「本机 DSH（DeepSeek Harness）」
   - 身体目录 `D:\大肥鱼`
   - 并引用注入原文：「大肥鱼运行在本机 DSH（DeepSeek Harness）上，身体目录是 D:\大肥鱼；只记忆这个工作区里的对话。」
   - 明确说「未调用任何工具」，排除了主动 recall 的可能。
4. 日志：`inject session=... hits=1 query=请只回答两个问题…`。

## 限制

- 召回是 bigram/LIKE，不是语义向量；同义改写可能漏。
- 没有按工作区分组过滤（数据库本身只进 `D:\大肥鱼` 的对话）。
- 子代理也会注入；后续可按 `agent` 类型跳过。
- `node:sqlite` 在 Node 24 仍标 Experimental，DSH 升级需复核。
- 插件不随 Git 同步，换机需重新安装。

## 回滚

```powershell
dsh plugin --profile desktop remove dafeiyu-memory-recall
```

或直接改 `D:\dsh-plugins\dafeiyu-memory-recall\index.js` 后重装。日志在 `~/.dsh/memory-v2/recall-bridge.log`。
