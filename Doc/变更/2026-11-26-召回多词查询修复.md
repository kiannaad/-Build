# 2026-11-26 召回多词查询修复

## 时间

2026-11-26 01:10–01:20（Asia/Shanghai）

## 原因

导入笔记后，用 `"游戏客户端开发 求职"` 召回返回空；单查 `"游戏"` 正常。原因：`_candidates` 把整句当成一个 FTS 精确短语，带空格就匹配不到。

## 改动

`db._candidates`：

- 按空白与中英文标点拆词；
- FTS 用 `"词1" OR "词2"`，任一命中即可；
- LIKE 回退同样按词 OR；
- 相似度从「排名倒数」改为「命中词数 / 总词数」，最低 0.2；
- 核心记忆匹配也改为任一词命中。

## 影响面

- 自然语言、多关键词查询不再因空格失败；
- 单关键词行为不变；
- 相似度更可解释，但仍是代理值，不是向量相似度。

## 验证证据

```text
Ran 65 tests in 5.737s
OK
```

真实召回：

```text
"游戏客户端开发 求职" → 命中「求职方向是游戏客户端开发，同时考虑测试开发。」
"陈裕佳" → 命中姓名记忆
```

新增测试：`test_recall_multi_term_any`。

## 限制

- 拆词是标点/空白级，不做分词；
- 多词全命中比单词命中分数高，但排序仍受重要度/置信度影响；
- FTS 与 LIKE 两套结果可能略有差异。

## 回滚

还原 `db._candidates` 与测试。
