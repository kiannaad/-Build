# 2026-11-25 模型提取实测

## 时间

2026-11-26 02:00–02:20（Asia/Shanghai）

## 原因

模型提取骨架与 MCP 工具早已就位，但本地只有 bge-m3（嵌入），没有 chat 模型。拉一个 1.5B 小模型，验证「规则提取漏掉的隐含事实」能否被模型补上。

## 改动

1. 安装 `qwen2.5:1.5b`（986 MB）。
2. `memory_extract_model` 增加可选 `model` 参数，未传时回退 `DFY_CHAT_MODEL`，避免必须重启宿主才能换模型。
3. 修解析：小模型在 `format=json` 下常直接返回**单个对象**而非数组；`parse_items` 现在兼容单对象。

## 实测

输入（规则提取不命中）：

```text
最近老是失眠，晚上两三点才睡着，白天没精神。
```

- `memory_ingest` → 候选 0（符合规则层预期）；
- 第一次 `memory_extract_model(model=qwen2.5:1.5b)` → 空；
- 查原始输出：模型返回的是单个对象 `{"body": "...", "kind": "user_fact", ...}`，解析器只认数组/包装对象，丢了；
- 修解析后重试 → 候选 `mem-7fe10354…`：
  - kind `user_fact`
  - body「最近老是失眠，晚上两三点才睡着，白天没精神」
  - tags `model-extract`
  - confidence 1.0（模型自报）
- 测试候选已 `memory_reject` 清理。

## 限制

- 1.5B 模型把「短期失眠」判成 `user_fact`，是否该长期记住值得商榷；仍须用户确认才激活。
- 只跑了一条样例，没有评估准确率/幻觉率。
- 仍是手动触发；没有接轮次钩子，也没有成本控制。
- 模型选择、提示词调优、批量评测都未做。

## 回滚

删除测试候选/事件即可；模型可 `ollama rm qwen2.5:1.5b`；工具不配模型时继续拒绝。
