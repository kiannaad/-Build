# 2026-11-25 记忆状态工具

## 时间

2026-11-25 23:55–00:05（Asia/Shanghai）

## 原因

记忆系统有事件、候选、核心、摘要、审计多个计数，但没有一个入口能快速回答「现在记住了多少、有没有待审、核心几条」。排查和日常查看都要跑 SQL。

## 改动

1. `db.stats(conn)`：返回 `events` 总数、`memories` 按状态分组、`core` 按状态分组、`digests`、`audit`。
2. MCP 新增 `memory_stats`（无参数）。
3. `tests/test_mcp.py` 增加统计断言。

## 影响面

- 工具变为 17 个。
- 只读查询，不改数据。
- 输出是聚合计数，不含记忆正文，适合直接展示。

## 验证证据

```text
Ran 43 tests in 2.750s
OK
```

真实 DSH 调用：

```json
{"events": 2, "memories": {"deleted": 2}, "core": {"confirmed": 1}, "digests": 1, "audit": 10}
```

（2 条事件与 2 条 deleted 记忆来自端到端测试；核心 1 条是重建事实；摘要 1 条是今天。）

## 限制

- 只有计数，没有体积/最旧最新时间/待审明细；候选明细用 `memory_candidates`。
- 统计不包括 `memory_embeddings`（向量尚未启用）。

还原 `db.py` / `mcp_server.py` 到上一提交并重启 MCP 服务。
