# 2026-11-25 语义召回压测与 numpy 加速

## 时间

2026-11-26 03:30–03:50（Asia/Shanghai）

## 原因

记忆条数会涨；Python 纯循环的余弦在 1000 条时可能拖慢每次召回。先压测，再决定要不要上 sqlite-vec。

## 压测条件

- 1000 条 active 记忆，每条 1024 维 float32 向量；
- 同一条查询重复 10 次取均值；
- 临时库，不碰真实数据。

## 结果

| 版本 | 语义召回/次 | 关键词/次 | 库大小 |
| --- | ---: | ---: | ---: |
| 纯 Python 循环 | 110.5 ms | 0.25 ms | 5.54 MB |
| numpy 矩阵（逐条解包） | 58.7 ms | 0.22 ms | 5.78 MB |
| **numpy 直接读 BLOB** | **21.8 ms** | **0.20 ms** | 5.78 MB |

## 改动

`embeddings.semantic_candidates`：

- 向量数 ≥32 时走 numpy：直接用 `np.frombuffer` 从 `memory_embeddings.vector` 建矩阵，一次矩阵乘；
- 小数据/无 numpy 时保留原纯 Python 余弦；
- `restricted` 过滤仍在 SQL 层完成。

测试 **61 项全过**（新增大批量向量路径）。

## 结论

- 当前真实记忆只有个位数，召回远快于压测值；
- 21.8 ms/1000 条对聊天注入可接受；
- **暂不引入 sqlite-vec**：等记忆到数千条或单次召回 >50ms 再上；
- 桥插件（Node/JS）的余弦是另一条路径，未纳入本次压测；它每次只对 active 记忆做一次线性扫描，量级相近。

## 回滚

删除 numpy 分支即回到纯 Python；不影响数据。
