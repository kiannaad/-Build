# 2026-11-25 召回桥向量融合

## 时间

2026-11-26 00:25–00:45（Asia/Shanghai）

## 原因

自动召回桥之前只用 bigram 关键词；bge-m3 就绪后，桥应该同时使用向量与关键词，才能覆盖改写查询。

## 改动

`D:\dsh-plugins\dafeiyu-memory-recall\index.js`：

- 读取 `memory_embeddings` 中 `DFY_EMBED_MODEL`（默认 `bge-m3`）的向量；
- 查询时调用本地 Ollama `/api/embed`（4 秒超时，单条缓存）；失败自动退回纯关键词；
- 每条记忆的相似度取 `max(关键词命中率, cosine(query, memory))`，再套原有精排公式；
- 核心记忆仍按关键词命中，排最前；
- 工作区隔离、去重、异常回退不变。

## 影响面

- 自动召回从「字面匹配」升级为「语义 + 字面」；
- 每个新查询多一次本地 Ollama 调用（首次加载模型较慢，之后通常几十毫秒）；
- Ollama 不在时自动退回关键词，不影响对话。

## 验证证据

1. 本地假嵌入测试：`node test.mjs` → `recall bridge test ok`，覆盖向量命中（无关键词重叠）、嵌入失败退回关键词、工作区隔离。
2. 真实库 + 真实 bge-m3：
   - 记忆「我喜欢在雨天听爵士乐」；
   - `recallHybrid("潮湿的天气适合放什么背景音")` → 返回 `["我喜欢在雨天听爵士乐"]`；
   - 关键词召回同一查询为空（上一轮已验证）。
3. Ollama 服务由后台任务 `pwsh-a4f0664ac68649c4` 常驻；模型 `bge-m3:latest` 1.16 GB。
4. 测试记忆已清理（status=deleted）。

## 限制

- 嵌入调用在 `system-prompt/assemble` 里同步 await，Ollama 冷启动可能让首个提示词慢几秒；
- 只有一条查询缓存，连续不同提问会重复嵌入；
- 仍是暴力余弦，记忆上千条后需要向量索引；
- 子代理/其它工作区仍按白名单隔离。

## 回滚

还原上一版 `index.js` 并重装插件；或设 `DFY_EMBED_MODEL` 为不存在的模型，桥会自动退回关键词。
