# 2026-11-25 备份恢复

## 时间

2026-11-26 01:00–01:15（Asia/Shanghai）

## 原因

之前只有备份与校验，没有恢复流程；单机方案必须能真的把库恢复回来，否则备份只是心理安慰。

## 改动

`MemoryService/backup.py` 新增 `restore(zip_path, memory_db, persona_dir, config_file, force=False)`：

- 先 `verify()` 校验 zip 与 manifest；
- 解压后对 `memory.db` 执行 `PRAGMA integrity_check`，不通过直接拒绝；
- 目标库已存在时**默认拒绝覆盖**，必须 `force=True`；
- `force=True` 时先把旧库另存为 `memory.db.pre-restore-<时间戳>`；
- 恢复 `memory.db`、`人格/*.md`、可选的 `cordis.patch.yml`；
- CLI 增加 `--restore <zip> [--force]`。

## 影响面

- 恢复会覆盖目标库与配置；必须停掉 MCP 服务再做（运行中的连接不会自动切换）。
- 不做「部分恢复」：要么整库，要么不动。
- 备份/恢复都不触碰凭据文件。

## 验证证据

```text
Ran 48 tests in 4.067s
OK
```

真实数据往返（不改线上库）：

```json
{
  "events_before": 5, "events_after": 5,
  "core_before": 1, "core_after": 1,
  "restored": ["memory.db", "persona/人设卡-v1.md", "persona/人设卡-v2.md", "persona/大肥鱼.md"]
}
```

另测：覆盖已存在库不带 force 会拒绝；带 force 会生成 `memory.db.pre-restore-*`。

## 限制

- 恢复期间服务必须停止，否则旧连接会继续用旧库。
- 没有自动恢复/回滚触发器；属于人工运维。
- 备份 zip 里不含会话日志与插件源码。

## 回滚

恢复本身可回滚：用生成的 `memory.db.pre-restore-*` 覆盖回去。
