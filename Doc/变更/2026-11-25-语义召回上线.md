# 2026-11-25 语义召回上线

## 时间

2026-11-26 00:05–00:25（Asia/Shanghai）

## 原因

向量层接口早就写好，但一直没有模型。bge-m3（1.2 GB）下载完成后，把真实语义召回接上，补掉「换个说法就召回不到」的短板。

## 改动

1. 安装 `bge-m3:latest`（Ollama，1.2 GB）。
2. `MemoryService/semantic.py`
   - `semantic_recall(query, embedder)`：查询向量 → `embeddings.semantic_candidates` → 与 `db.recall` 相同的精排（重要度/置信度/保持率/强化）；
   - `embed_all(conn, embedder)`：补缺失向量。
3. MCP 新增：
   - `memory_embed`：给缺向量的记忆补嵌入（Ollama，默认 bge-m3）；
   - `memory_semantic_recall`：语义召回。
4. `tests/test_semantic.py`（3 项，假 3 维嵌入器，不联网）。

## 影响面

- 工具变为 19 个。
- 嵌入完全本地（Ollama 回环），不把记忆发给外部服务；`restricted` 仍不嵌入。
- 向量存在 `memory_embeddings`，DB 会随记忆数量增长；bge-m3 为 1024 维。

## 验证证据

```text

```

真实 DSH 链路：

1. `memory_ingest`「我喜欢在雨天听爵士乐。」→ 候选 → `memory_promote` 激活
2. `memory_embed` → `embedded: 1`
3. `memory_semantic_recall("潮湿的天气适合放什么背景音")`
   → 命中「我喜欢在雨天听爵士乐」，**similarity 0.7165，score 0.5911**
4. 同一查询 `memory_recall`（关键词）→ **空**，证明语义召回确实补上了改写场景
5. 测试记忆已 `memory_forget` 清理

## 限制

- **自动召回桥仍用 bigram**，语义召回目前要模型主动调用；下一步把桥升级为「向量 + 关键词」。
- 嵌入在 MCP 请求线程里同步执行，首次加载模型较慢；批量补向量建议在空闲时跑。
- 没有向量索引（sqlite-vec），当前是暴力余弦；记忆上千条后需要优化。

## 回滚

删除 `semantic.py` 与两个工具，或把 `DFY_EMBED_MODEL` 指向不存在的模型让调用失败；已存向量可保留。
