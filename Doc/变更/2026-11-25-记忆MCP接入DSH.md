# 2026-11-25 记忆 MCP 接入 DSH

## 时间

2026-11-25 18:55–19:20（Asia/Shanghai）

## 原因

把 `MemoryService` 接进 DSH，让模型能像调用原生工具一样读写 v2 记忆；这是记忆 v2 从「可运行代码」变成「大肥鱼可用能力」的一步。

## 改动

1. 在 `profiles/desktop/cordis.patch.yml` 追加 `dsh-mcp-client` 行：
   - `serverName: dafeiyu_memory`
   - `transport: stdio`
   - `command: C:\...\Python314\python.exe`
   - `args: ['D:\大肥鱼\MemoryService\mcp_server.py']`
   - `env.DSH_MEMORY_DB: C:\Users\XHLENOVO\.dsh\memory-v2\memory.db`
2. 备份：`cordis.patch.yml.bak-20261125-1900`。
3. 修 MCP 服务编码：Windows 下 stdin/stdout 默认按本地代码页，中文会乱码/变代理字符；启动时强制 `utf-8`。

## 影响面

- 新增 4 个工具：`mcp__dafeiyu_memory__memory_recall / memory_remember / memory_forget / memory_audit`，带命名空间，不与 soul-md 的 `memory_*` 冲突。
- 运行库落在 `~/.dsh/memory-v2/memory.db`，不进 Git。
- 未改其它插件配置。

## 验证证据

1. MCP 服务进程启动：`python.exe ... D:\大肥鱼\MemoryService\mcp_server.py`；杀掉后客户端自动重连（新 PID）。
2. `memory_audit` 首次调用返回 `{"entries": []}`，数据库自动创建（`memory.db`，131 KB）。
3. 端到端（全部经 MCP）：
   - 先造一条 L3 事件：`ev-2a2109c043b846e9807060cfe709f335`（「主人喜欢喝乌龙茶」）。
   - `memory_remember` → `mem-267e48a3ff2e416b83ac188db2f3cbf3`。
   - `memory_recall("乌龙茶")` → 1 条，score 0.885，retention 1.0。
   - `memory_forget` → ok。
   - 再 `memory_recall("乌龙茶")` → 空。
4. 中文输入输出正常（修复前 `memory_remember` 报 `surrogates not allowed`）。

## 关闭 soul-md 记忆（避免双记忆）

- 修改 `cordis.patch.yml` 的 `soul-md.memory`：`inject: false`、`disabledCards: [大肥鱼]`；备份 `cordis.patch.yml.bak-20261125-1925`。
- 验证：`memory_read` 返回 `Error: Memory is disabled for persona "大肥鱼"`；`soul_read` 仍能回读人设全文；`mcp__dafeiyu_memory__memory_audit` 仍正常返回 create/deleted 记录。

## 限制

- 没有自动召回：DSH `agent/pre-step` 注入尚未实现，模型需主动调用工具。
- 没有向量：召回仍是 FTS/LIKE 代理。
- 没有候选提取器与每日衰减任务；旧库未迁移。
- soul-md 仍保留自己的记忆工具（当前为空），v2 稳定后应关闭，避免双记忆。

## 回滚

还原 `cordis.patch.yml.bak-20261125-1900` 并重启；或删除新增的 `mcp-dafeiyu-memory` 条目。删除 `~/.dsh/memory-v2/` 清空测试数据。
