# 2026-11-25 候选审核闭环

## 时间

2026-11-25 22:45–23:00（Asia/Shanghai）

## 原因

自动提取会不断产生 `candidate`，但此前只能通过 SQL 查看，聊天里没有「看候选 / 拒绝候选」的入口，审核闭环是断的。

## 改动

1. `db.py`
   - `list_candidates(limit)`：按创建时间倒序列出待审候选。
   - `reject_candidate(id, reason)`：仅 `candidate` 可拒绝；置 `status=deleted`（软删除，可恢复），写 `reject` 审计；非候选报错。
2. `mcp_server.py` 新增 `memory_candidates` / `memory_reject`。
3. `tests/test_mcp.py` 覆盖：ingest 产生候选 → 列出 → 拒绝 → 列表为空 → 重复拒绝报错。

## 影响面

- DSH 工具变为 14 个。
- 拒绝是软删除，数据仍在库里，可恢复；不会物理删除。
- 候选不会自动变成正式记忆，仍需 `memory_promote`。

## 验证证据

```text

```

真实 DSH 链路：

1. `memory_ingest`「我养了一只叫年糕的橘猫。」→ `ev-8e881d48…`，候选 `mem-aaa42f2e…`
2. `memory_candidates` → 1 条（kind=user_fact，tags=auto-extract）
3. `memory_reject` → `ok`，status=deleted
4. 再次 `memory_candidates` → 空

## 限制

- 候选列表没有分页/筛选，只有 limit。
- 拒绝后恢复需要手动把 status 改回 candidate 或新增 restore 工具。
- 还没有审核界面，只在对话里通过工具操作。

## 回滚

还原 `db.py` / `mcp_server.py` 到上一提交并重启 MCP 服务。
