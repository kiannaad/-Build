# 2026-11-25 自动每日备份

## 时间

2026-11-26 03:15–03:30（Asia/Shanghai）

## 原因

备份此前只能手动跑；单机方案里「忘了备份」是最现实的风险。心跳已经每 10 分钟运行，顺手把「每天最多一份备份」接进去。

## 改动

1. `backup.list_backups(target)` / `backup.prune(target, keep=7)`：按 mtime 排序，只保留最近 N 份。
2. `auto_tick._ensure_daily_backup()`：
   - `DFY_AUTO_BACKUP=0` 可关闭；
   - 目录 `DFY_BACKUP_DIR`，默认 `D:\大肥鱼\Backups`；
   - 当天已有 `dafeiyu-YYYYMMDD-*` 就跳过；
   - 新建后按 `DFY_BACKUP_KEEP`（默认 7）裁剪。
3. `memory_tick` 返回值新增 `backup` 字段（当天新建时为路径，否则 null）。
4. 测试：心跳调用备份、`prune` 保留最近 2 份。

## 影响面

- 每天最多一份 zip；不会因 10 分钟心跳产生 144 份。
- 备份失败只记 stderr，不阻断入库/摘要。
- 备份包含记忆库、人设、profile 配置；不含凭据与会话日志。


真实心跳（当天 17:13 已有备份）：

```json
{"ingest": {…}, "digest_day": "2026-11-25", "stale": 0, "backup": null}
```

## 限制

- 「当天一份」按文件名日期判断；手动删掉当天备份后，下一次心跳会补一份。
- 保留份数按文件修改时间，不看内容大小。
- 恢复仍需停 MCP 服务后手动 `--restore`。

## 回滚

`DFY_AUTO_BACKUP=0` 即可关闭自动备份；已生成的 zip 可手动删除。
